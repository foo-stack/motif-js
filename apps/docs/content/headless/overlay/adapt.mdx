# Adapt

<Lede>
  `Adapt` renders a [Dialog](/headless/overlay/dialog) above a breakpoint and a
  [Drawer](/headless/overlay/drawer) (a bottom sheet) within it — the same content, the same open
  state, the right shape for the viewport. Drop it in place of `Dialog.Content`; nothing else about
  the composition changes.
</Lede>

<ArticleMeta />

## What it is

A `Drawer` is already a `Dialog` underneath — same `Dialog.Root`, same open-state context, just a
different `Content` presentation. `Adapt` leans on exactly that: it picks `Dialog.Content` or
`Drawer.Content` from the viewport and renders it inside your existing `Dialog.Root`. The trigger,
title, description, and close all keep working across the swap because they read the shared context,
not the presentation.

This replaces the usual hand-rolled branch:

<CodeBlock lang="tsx" code={`// Before — two trees, duplicated content, a viewport hook at the call site
const compact = useViewportMatch(undefined, 'md');
return compact
  ? <Drawer.Root>…</Drawer.Root>
  : <Dialog.Root>…</Dialog.Root>;`} />

## Usage

<CodeBlock lang="tsx" code={`import { Dialog, Adapt } from '@usemotif/headless';

<Dialog.Root>
  <Dialog.Trigger>
    <button>Settings</button>
  </Dialog.Trigger>
  <Adapt below="md" side="bottom">
    <Dialog.Title>Settings</Dialog.Title>
    <Dialog.Description>Manage your preferences.</Dialog.Description>
    <Dialog.Close><button>Done</button></Dialog.Close>
  </Adapt>
</Dialog.Root>`} />

Above `md` this is a centered modal; below `md` it is a sheet anchored to the bottom edge. The same
JSX, one open state.

## API

<ApiSignature
  name="Adapt"
  status="stable"
  signature={`function Adapt(props: AdaptProps): ReactElement | null`}
/>

`AdaptProps` extends `DialogContentProps`, so every `Dialog.Content` prop — `exitDurationMs`,
`dismissOnEscape`, `dismissOnScrimClick`, `style`, `children` — forwards to whichever presentation
is active. The adapt-specific props:

| Prop | Type | Default | Purpose |
| --- | --- | --- | --- |
| `below` | `BreakpointName` | `'md'`¹ | Adapt to a drawer when the viewport is strictly below this breakpoint. |
| `above` | `BreakpointName` | — | Adapt to a drawer when the viewport is at or above this breakpoint. |
| `side` | `'left' \| 'right' \| 'top' \| 'bottom'` | `'bottom'` | Which edge the drawer anchors to when adapted. `'bottom'` is a sheet. |

¹ `below` defaults to `'md'` only when neither `below` nor `above` is set — so the bare
`<Adapt>` is "dialog on desktop, sheet on mobile" with no configuration.

<Callout variant="info" title="Cross-platform">
  On native, `Adapt` reads the window width from `Dimensions`; the public API is identical and the
  breakpoint comes from the same `defaultBreakpoints` used everywhere else. `side` is advisory on
  native — the native drawer's edge is driven by your `style` (matching `Drawer.Content`'s own
  `position`), so it isn't forwarded there.
</Callout>

## Notes

- `Adapt` must live inside a `Dialog.Root` — it renders a `Content`, not a root.
- The swap happens on resize. Because the open state lives in `Dialog.Root`, an overlay that's open
  when the viewport crosses the breakpoint stays open, re-presented in the new shape.
- For asymmetric enter/exit timing on either shape, see [style props](/reference/style-props); to
  run the animation off the main thread, see [motion drivers](/reference/motion-drivers).
