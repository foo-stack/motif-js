# The @usemotif/ui kit

<Lede>
  Where [recipes](/recipes/component-recipes) give you styling data, `@usemotif/ui` gives you the
  finished components — already themed, already interactive, already adaptive. It's the
  batteries-included layer, kept in a leaf package so core stays unopinionated and you only pay for
  what you import.
</Lede>

<ArticleMeta />

## What's in it

The kit fills the gap between the primitives (`@usemotif/react` already ships Button, Avatar,
typography, layout) and the unstyled headless behaviours. It wraps recipes and headless parts into
ready components:

| Component | Built from |
| --- | --- |
| `Card` | `cardRecipe` over `Box` |
| `Badge` | `badgeRecipe` over `Box` |
| `Spinner` | `Box` + a `keyframes` rotation; honours reduced-motion |
| `Alert` | composed `Box` + `Text`; soft intent tint (`neutral` · `info` · `success` · `warning` · `danger`) from the `status` tokens |
| `Modal` | headless `Dialog` + `Adapt` + a themed, animated surface |
| `Tooltip` | headless `Tooltip` + a themed inverse-surface bubble |
| `Toaster` / `useToast` | headless toaster + themed `surface.raised` toast cards |
| `Switch` | a real `<input role="switch">`; track + sliding thumb in pure CSS via `_checked` |
| `Tabs` | headless `Tabs` (roving focus, arrow keys) via `asChild`; active tab coloured by `_selected` |
| `Checkbox` | a real `<input type="checkbox">`; fill + tick in pure CSS via `_checked` |
| `Radio` / `RadioGroup` | real `<input type="radio">` grouped by a shared `name`; ring + dot via `_checked` |
| `Popover` | headless `Popover` (floating position, dismiss) + a themed `surface.raised` panel |
| `Accordion` | headless `Accordion` (single/multiple) via `asChild`-style triggers; chevron + colour flip via `_expanded` |
| `Select` | one controlled component over headless `Select` (listbox, keyboard nav); themed trigger + options |
| `Menu` | headless `Menu` (roving focus) with `asChild` items, so the themed row highlights on `_hover` + `_focus` |
| `Slider` | headless `Slider` (drag + arrow keys) with a themed track, fill, and thumb |
| `Progress` | headless `Progress`; determinate bar that eases, or an indeterminate sweep (static under reduced-motion) |
| `Drawer` / `Sheet` | side-anchored headless `Dialog`; themed surface that slides in/out via the motion driver |

<CodeBlock lang="bash" code={`npm install @usemotif/ui`} />

<Callout variant="info" title="Pay only for what you import">
  The kit is code-split per component. Importing `Card` pulls its primitives and recipe — not
  `Modal`'s `@usemotif/headless` dependency. A display-only app never bundles the overlay layer.
</Callout>

## Display

<CodeBlock lang="tsx" code={`import { Card, Badge, Spinner, Alert } from '@usemotif/ui';

<Card elevation="raised" padding="lg">
  <Badge intent="success">Live</Badge>
</Card>

<Spinner size={24} />

<Alert intent="danger" title="Payment failed">
  Update your card and try again.
</Alert>`} />

## Modal — themed, adaptive, animated

`Modal` is the kit's showcase: it composes the accessible headless `Dialog` (focus trap, scrim,
Escape) with a themed surface that **shapeshifts** into a bottom sheet on small screens (via
[`Adapt`](/headless/overlay/adapt)) and **animates** in through the active motion driver.

<CodeBlock lang="tsx" code={`import { Modal } from '@usemotif/ui';
import { Button } from 'usemotif';

<Modal.Root>
  <Modal.Trigger><Button>Delete…</Button></Modal.Trigger>
  <Modal.Content>
    <Modal.Title>Delete project?</Modal.Title>
    <Modal.Description>This cannot be undone.</Modal.Description>
    <Modal.Close><Button intent="danger">Delete</Button></Modal.Close>
  </Modal.Content>
</Modal.Root>`} />

Above the `sm` breakpoint it's a centered dialog; below it, a bottom sheet — same markup, one open
state. Tune the adapt breakpoint with `below`/`above` and the exit timing with `exitDurationMs` on
`Modal.Content` (it forwards every [`Adapt`](/headless/overlay/adapt) prop).

## Tooltip and Toast

`Tooltip` wraps the accessible headless tooltip (hover/focus open with delays, `aria-describedby`,
portal positioning) in a themed inverse-surface bubble:

<CodeBlock lang="tsx" code={`import { Tooltip } from '@usemotif/ui';
import { Button } from 'usemotif';

<Tooltip.Root>
  <Tooltip.Trigger><Button>Save</Button></Tooltip.Trigger>
  <Tooltip.Content>Saved automatically</Tooltip.Content>
</Tooltip.Root>`} />

`Toaster` mounts once near your app root; `useToast()` pushes themed toasts from anywhere. Each card
is a `surface.raised` surface, and the headless layer keeps the `role="alert"` / `role="status"`
live-region semantics and auto-dismiss:

<CodeBlock lang="tsx" code={`import { Toaster, useToast } from '@usemotif/ui';
import { Button } from 'usemotif';

function App() {
  return (
    <Toaster>
      <SaveButton />
    </Toaster>
  );
}

function SaveButton() {
  const { toast } = useToast();
  return <Button onPress={() => toast({ title: 'Saved', description: 'Your changes are stored.' })}>Save</Button>;
}`} />

## Form controls — pure-CSS state

`Switch`, `Checkbox`, and `Radio` are **real form-native inputs** — keyboard-operable,
label-associable, and submit with a `<form>` like any `<input>`. Their checked appearance (the
switch thumb, the checkbox tick, the radio dot) is painted entirely by the [`_checked`
pseudo-state](/reference/style-props#pseudo-states), so they need **no controlled React state** to
look right:

<CodeBlock lang="tsx" code={`import { Switch, Checkbox, Radio, RadioGroup } from '@usemotif/ui';

<label><Checkbox defaultChecked /> Email me updates</label>

<Switch defaultChecked onChange={(e) => save(e.currentTarget.checked)} />

<RadioGroup name="plan" defaultValue="pro">
  <label><Radio value="free" /> Free</label>
  <label><Radio value="pro" /> Pro</label>
</RadioGroup>`} />

`RadioGroup` hands its children a shared `name`, so the browser gives you single-selection and
arrow-key navigation natively — and wraps them in a `role="radiogroup"`. Want controlled selection?
Put `checked`/`onChange` straight on each `Radio`; they're ordinary inputs.

## Popover — a themed floating panel

`Popover` wraps the headless `Popover` (trigger `aria-expanded` wiring, floating positioning,
Escape + click-outside dismissal) in a themed `surface.raised` card. `Root`, `Trigger`, and `Close`
are the headless parts; `Content` carries the theming:

<CodeBlock lang="tsx" code={`import { Popover } from '@usemotif/ui';
import { Button } from 'usemotif';

<Popover.Root>
  <Popover.Trigger><Button>Filters</Button></Popover.Trigger>
  <Popover.Content placement="bottom" offset={8}>
    …filter controls…
    <Popover.Close><Button>Done</Button></Popover.Close>
  </Popover.Content>
</Popover.Root>`} />

`Content` forwards every headless prop — `placement`, `offset`, `dismissOnClickOutside`,
`dismissOnEscape` — so positioning and dismissal stay tunable.

## Accordion — open state in pure CSS

`Accordion` themes the headless `Accordion` (single- or multiple-open, controlled or uncontrolled).
The headless trigger clones its disclosure semantics onto a themed `Box as="button"`, which then
**recolours and flips its chevron straight from `aria-expanded`** via the [`_expanded`
pseudo-state](/reference/style-props#pseudo-states) — no JS reads the open state:

<CodeBlock lang="tsx" code={`import { Accordion } from '@usemotif/ui';

<Accordion.Root type="single" defaultValue={['shipping']}>
  <Accordion.Item value="shipping">
    <Accordion.Trigger>Shipping</Accordion.Trigger>
    <Accordion.Content>Ships in 2–3 business days.</Accordion.Content>
  </Accordion.Item>
  <Accordion.Item value="returns">
    <Accordion.Trigger>Returns</Accordion.Trigger>
    <Accordion.Content>30-day returns, no questions asked.</Accordion.Content>
  </Accordion.Item>
</Accordion.Root>`} />

Pass `type="multiple"` to let several panels stay open at once, or drive `value`/`onValueChange`
for controlled open state.

## Select — one component, full keyboard listbox

The headless `Select` is a compound (you wire `Root`/`Trigger`/`List` and render the selected label
yourself). The kit collapses it into **one controlled component**: pass `options`, and it owns the
trigger label, the themed listbox, and per-option highlight/selected styling. It's controlled or
uncontrolled, and the trigger flips its chevron on open via `_expanded`:

<CodeBlock lang="tsx" code={`import { Select } from '@usemotif/ui';

<Select
  options={[
    { value: 'utc', label: 'UTC' },
    { value: 'est', label: 'Eastern (EST)' },
    { value: 'pst', label: 'Pacific (PST)' },
  ]}
  defaultValue="utc"
  onValueChange={(v) => setZone(v)}
/>`} />

Arrow keys, Home/End, type-to-open, and click-outside dismissal all come from the headless layer.
Disabled options are skipped by keyboard navigation and dimmed.

## Menu — themed dropdown, accessible by focus

`Menu` themes the headless `Menu` (roving focus, arrow-key navigation, Escape + click-outside). Its
items use `asChild`, so **the themed row is itself the focusable element** — it highlights on
`_hover` *and* `_focus`, so keyboard navigation lights up the active item, not just the mouse:

<CodeBlock lang="tsx" code={`import { Menu } from '@usemotif/ui';
import { Button } from 'usemotif';

<Menu.Root>
  <Menu.Trigger><Button>Actions</Button></Menu.Trigger>
  <Menu.Content>
    <Menu.Item onSelect={rename}>Rename</Menu.Item>
    <Menu.Item onSelect={duplicate}>Duplicate</Menu.Item>
    <Menu.Separator />
    <Menu.Item disabled>Archive</Menu.Item>
  </Menu.Content>
</Menu.Root>`} />

## Slider and Progress — value, in and out

`Slider` themes the headless `Slider` (pointer drag, arrow-key / Home / End / PageUp-Down, full
`aria-valuenow`); `Progress` themes the `role="progressbar"`. A `Progress` with a number eases to
the new width; `value={null}` runs an indeterminate sweep that **collapses to a static bar under
`prefers-reduced-motion`**:

<CodeBlock lang="tsx" code={`import { Slider, Progress } from '@usemotif/ui';

<Slider defaultValue={40} min={0} max={100} aria-label="Volume" onValueChange={setVolume} />

<Progress value={70} aria-label="Uploading" />   {/* determinate */}
<Progress value={null} aria-label="Loading" />   {/* indeterminate sweep */}`} />

## Drawer and Sheet — panels that slide

`Drawer` is a side-anchored `Modal`: the same accessible headless `Dialog` (focus trap, scrim,
Escape), but the themed surface **slides in from its `side`** through the active motion driver and
slides back out on close. `Sheet` is a `Drawer` pinned to the bottom edge — the mobile action-sheet
pattern:

<CodeBlock lang="tsx" code={`import { Drawer, Sheet } from '@usemotif/ui';
import { Button } from 'usemotif';

<Drawer.Root>
  <Drawer.Trigger><Button>Menu</Button></Drawer.Trigger>
  <Drawer.Content side="left">
    <Drawer.Title>Navigation</Drawer.Title>
    …links…
  </Drawer.Content>
</Drawer.Root>

<Sheet.Root>
  <Sheet.Trigger><Button>Share</Button></Sheet.Trigger>
  <Sheet.Content>…actions…</Sheet.Content>
</Sheet.Root>`} />

Pick the edge with `side` (`left` · `right` · `top` · `bottom`, default `right`), and tune the
slide-out timing with `exitDurationMs` on `Drawer.Content` / `Sheet.Content`.
