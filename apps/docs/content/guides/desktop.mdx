# Desktop

<Lede>
  Motif treats desktop as a first-class target, not an afterthought. One shared component, built
  only on the primitives identical across web and native, is wired into four desktop shells:
  Electron and Tauri load motif&rsquo;s web bundle, react-native-windows and react-native-macos load
  its native bundle. The two web shells are built and smoke-tested here; the two react-native shells
  are scaffolded and not yet runnable in this repository.
</Lede>

<ArticleMeta />

## One component, four shells

The examples under [`examples/`](https://github.com/foo-stack/usemotif/tree/main/examples) share a
single `<DemoScreen/>`, written only on the primitives that are byte-for-byte the same on web and
native - `Box`, `Stack`, `Text`, `Button`, tokens, and `ThemeProvider`. Every target imports that
one file; the bundler resolves web vs native through motif&rsquo;s export conditions. The component
never branches on platform.

<CodeBlock lang="tsx" code={`// examples/desktop-shared - imported unchanged by every target
export function DemoScreen() {
  return (
    <ThemeProvider themes={[light, dark]} active={active}>
      <Box bg="$colors.surface.base" p="$6">
        <Text fontSize="$xl" fontWeight="$bold">motif on the desktop</Text>
        {/* ...Stack / Text / Button only... */}
      </Box>
    </ThemeProvider>
  );
}`} />

## Two paths to a desktop window

- **Web shell** - a desktop window hosting motif&rsquo;s **web** bundle. The `desktop-web` Vite app
  renders `<DemoScreen/>` via `@usemotif/react` and builds to a static `dist` (with `base: './'` so
  it loads over `file://`). **Electron** and **Tauri** both point a window at that same build.
- **Real React Native** - motif&rsquo;s **native** bundle running on desktop. The `desktop-rn` app
  renders the same `<DemoScreen/>` via `@usemotif/react-native`, built by **react-native-windows**
  and **react-native-macos**.

## The four targets

| Target | Path | How it&rsquo;s proven |
| --- | --- | --- |
| Electron | web shell | Builds the web payload and launches a window; a Playwright-Electron smoke asserts the demo painted. |
| Tauri | web shell | Compiles the Rust shell, which embeds the web build via `generate_context!`. The build is the proof. |
| react-native-macos | real RN | Scaffolded, not yet runnable here. There is no CI lane. |
| react-native-windows | real RN | Scaffolded, not yet runnable here. There is no CI lane. |

The **Desktop** workflow (`.github/workflows/desktop.yml`) has two jobs, one for each web shell.
Like the performance lane, it is intentionally **not** a required check: desktop runners are heavier
and slower than unit CI, so it runs alongside without blocking merges.

The react-native lanes were removed. The RN init tooling (`react-native-macos-init` and
`react-native-windows-init`) cannot run inside the monorepo workspace: it injects `--workspace` into
internal npm calls that reject it. They need an out-of-workspace setup before they can come back,
and the workflow says so in its own comments.

<Callout variant="warning" title="Honest status">
  Only the two web-shell targets are proven. Electron builds, launches, and asserts the demo painted;
  Tauri compiles the Rust shell over the same web build. Both run in CI.

  The two react-native shells are **scaffolded and not currently runnable here**. Nothing builds them
  on this repository, so treat them as a demonstration of the shared-component approach rather than a
  supported target.
</Callout>

## The React Native version lag

react-native-windows and -macos track React Native, but **lag** it. This monorepo pins
RN&nbsp;0.83.6 through a root `resolutions` entry, ahead of what either project supports, which is
the reason those two shells are not built here.

The `desktop-rn` example declares no dependencies of its own: it is the shared screen and its shell
scaffolding, with the React Native toolchain deliberately absent so an older one never touches the
rest of the repo. Provisioning it is a local, out-of-workspace step. The web-shell targets have no
such constraint, because they consume the same `@usemotif/react` build the web ships.

## Run them

```sh
# Web shell - build the payload, then launch Electron (or run its smoke test).
yarn workspace @usemotif/example-desktop-web build
yarn workspace @usemotif/example-desktop-electron start

# Tauri - compile the Rust shell over the same build.
cargo build --manifest-path examples/desktop-tauri/src-tauri/Cargo.toml
```

The react-native targets have no CI lane and no one-line local command. See
[`examples/desktop-rn/README.md`](https://github.com/foo-stack/usemotif/tree/main/examples/desktop-rn)
for what provisioning them involves.
