## Define a theme

`createTheme()` is a tiny pass-through factory. It does not transform anything; it exists to narrow the `tokens` type so `$`-references in callers are typed against the scale they reach for.

```tsx
import { createTheme } from '@motif-js/react';

export const light = createTheme({
  name: 'light',
  tokens: {
    colors: {
      surface: { base: '#FBF7F2', muted: '#F5EFE6' },
      text: { default: '#1C1917', muted: '#57534E' },
      accent: '#C2410C',
    },
    space: { 1: 4, 2: 8, 3: 12, 4: 16, 5: 20, 6: 24 },
    radii: { sm: 4, md: 6, lg: 12 },
  },
});

export const dark = createTheme({
  name: 'dark',
  tokens: {
    colors: {
      surface: { base: '#13110E', muted: '#1A1714' },
      text: { default: '#FBF7F2', muted: '#C7BFB1' },
      accent: '#EA580C',
    },
    space: { 1: 4, 2: 8, 3: 12, 4: 16, 5: 20, 6: 24 },
    radii: { sm: 4, md: 6, lg: 12 },
  },
});
```

The `name` is the identifier the cascade uses. A theme without a name cannot be activated; a theme with a duplicate name overrides the earlier registration.

## Activate at the root

`ThemeProvider` registers every theme it knows about and activates one of them. Pass an array of themes and the name of the one you want active.

```tsx
import { ThemeProvider } from '@motif-js/react';
import { light, dark } from './theme';

export function App({ children, mode }) {
  return (
    <ThemeProvider themes={[light, dark]} active={mode}>
      {children}
    </ThemeProvider>
  );
}
```

`<ThemeProvider>` emits a single `<style>` element containing every theme's tokens, scoped to `[data-theme="<name>"]`. It then wraps `children` in a `<div data-theme={active}>`. Switching themes amounts to changing the `active` prop; the cascade does the rest, and no Motif components re-render.

## Sub-themes for parts of the page

The `<Theme>` boundary swaps the active theme for a subtree. Use it for marketing surfaces where one section needs to live in dark even though the rest of the app is light.

```tsx
import { Theme } from '@motif-js/react';

export function MarketingPage() {
  return (
    <>
      <NavBar />
      <Theme name="dark">
        <Hero />
      </Theme>
      <FeatureGrid />
    </>
  );
}
```

The hero renders against the dark theme even though the parent provider's active theme is light. Components inside `<Theme>` read tokens from the swapped theme; components outside continue to use the parent's.

## Composable sub-themes

Themes compose by name. If you register `light`, `dark`, `light_red`, and `dark_red`, then nesting `<Theme name="red">` inside `<ThemeProvider active="dark">` resolves to `dark_red` automatically. The chain is dot-walked — first the full chain (`dark_red_blue`), then the inner name (`red`), then the parent's active.

```tsx
<ThemeProvider themes={[light, dark, light_red, dark_red]} active="dark">
  <Box bg="$colors.surface.base" /> {/* dark */}
  <Theme name="red">
    <Box bg="$colors.surface.base" /> {/* dark_red */}
  </Theme>
</ThemeProvider>
```

The combinations you care about are pre-registered with `createTheme()` and passed in `themes`. Anything you do not pre-register falls back to the inner name or to the parent — there is no implicit walk that would surprise you at runtime.

<Callout kind="info" title="Why pre-register">
  Sub-themes feel like inheritance, but they are not. We deliberately do not synthesize combinations
  on the fly — that path produces specificity bugs that are hard to debug. Pre-registering each
  combination keeps the resolution deterministic.
</Callout>

## Read the active theme from a hook

Most styling does not need to know the active theme — `$`-references resolve automatically. When you do need the name (for an `<img src>` swap, for a third-party widget that does not read CSS variables, for analytics), `useThemeName()` gives it to you.

```tsx
import { useThemeName } from '@motif-js/react';

function Logo() {
  const theme = useThemeName();
  return <img src={theme === 'dark' ? '/logo-dark.svg' : '/logo-light.svg'} alt="Motif" />;
}
```

There is also `useTheme()` for direct access to the resolved tokens object — useful when you need to compute a style at runtime, but rare in well-typed app code.

## Switch themes at runtime

Theme state is yours to own. The most common pattern is a small hook that persists the choice and feeds the result into `<ThemeProvider active>`.

```tsx
import { useEffect, useState } from 'react';
import { ThemeProvider } from '@motif-js/react';
import { light, dark } from './theme';

function useThemeMode() {
  const [mode, setMode] = useState<'light' | 'dark'>('light');
  useEffect(() => {
    const stored = localStorage.getItem('theme');
    if (stored === 'dark' || stored === 'light') setMode(stored);
  }, []);
  const set = (next: 'light' | 'dark') => {
    setMode(next);
    localStorage.setItem('theme', next);
  };
  return { mode, set };
}

export function App({ children }) {
  const { mode } = useThemeMode();
  return (
    <ThemeProvider themes={[light, dark]} active={mode}>
      {children}
    </ThemeProvider>
  );
}
```

The hook itself is plain React; Motif's only contribution is the `active` prop wiring. A `prefers-color-scheme` listener, a server-side cookie, a per-route override — every one of those slots into this same `useThemeMode()` shape.
