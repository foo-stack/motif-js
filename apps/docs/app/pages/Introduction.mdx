## Why we wrote it

Most styling libraries pick a side. They are built for the web and ported to native, or built for native and asked to behave on web. We did not want to choose. Motif compiles a single style declaration to atomic CSS classes on the web and to platform style objects on iOS and Android. Tokens resolve at build time. Variants are statically analyzable. Themes swap without re-render storms.

It is a small library — a handful of kilobytes gzipped — that does one thing well: it lets you describe how something looks, in a language that travels.

## What you get

- A style-prop API on every primitive — `<Box p="$5" bg="$colors.surface.raised">`
- A `styled()` factory for component-level reuse
- A two-layer token system: raw scales for designers, semantic surface and text tokens for components
- Container queries, media queries, and three responsive syntaxes
- A static compiler that extracts what it can; a runtime that always works

## The shape of a styled component

```tsx
import { Box, Heading, Paragraph, ThemeProvider } from '@motif-js/react';
import { lightTheme } from '@motif-js/tokens';

export function Hello() {
  return (
    <ThemeProvider themes={[lightTheme]} active="light">
      <Box
        p="$5"
        bg="$colors.surface.raised"
        borderRadius="$radii.lg"
        borderWidth={1}
        borderStyle="solid"
        borderColor="$colors.border.muted"
      >
        <Heading level={1}>Hello, motif</Heading>
        <Paragraph color="$colors.text.muted">
          The same component renders on web and on native.
        </Paragraph>
      </Box>
    </ThemeProvider>
  );
}
```

The keys you see — `$5`, `$colors.surface.raised`, `$radii.lg` — are token references. They resolve from the active theme. Rename a token in one place and every component that references it updates.

<Callout kind="tip" title="Tokens are the lever you pull">
  Three months from now your designer will hand you a small color tweak. If your accent is a token
  it is a one-line change. If it is hard-coded into seven components it is an afternoon — and one of
  them will be missed.
</Callout>

## How the pieces fit

Motif ships as a small set of focused packages. You install one — `@motif-js/react` — and the others come along as transitive dependencies of the parts you use.

| Package                  | What it gives you                                                                           |
| ------------------------ | ------------------------------------------------------------------------------------------- |
| `@motif-js/react`        | The React bindings. Import primitives, hooks, and `createTheme()` from here.                |
| `@motif-js/tokens`       | A default `lightTheme` and `darkTheme` you can use directly or extend.                      |
| `@motif-js/headless`     | Accessible behavior wrappers: Dialog, Tooltip, Combobox, Tabs. No styling — you bring that. |
| `@motif-js/icons`        | A typed Lucide wrapper that renders through the `Icon` primitive.                           |
| `@motif-js/reset`        | A small CSS reset, mountable as the `<MotifReset />` component for SSG-friendly use.        |
| `@motif-js/compiler-swc` | The build-time style extractor. Plug it into Vite, Next, or any unplugin-aware bundler.     |

Each one is independently versioned but always shipped together — pick the same version across the board.

## What ships when

Motif resolves your styles in two phases. The compiler extracts what it can statically — token references, responsive props, pseudo-state bags, variant maps — into atomic CSS classes baked into your bundle. Anything dynamic falls through to a small runtime that injects classes on demand.

The split is invisible at the call site. You write the same JSX either way. The compiler is an optimization, not a gate; everything works the same in development without it. When you turn it on for production, the dynamic path stays in place as a safety net for values the compiler cannot pin down at build time.

<Callout kind="info" title="No Babel required">
  The static extractor runs on top of SWC and is wired in via a single Vite plugin. You do not need
  to set up a Babel config or maintain a parallel build pipeline.
</Callout>
