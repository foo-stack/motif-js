# @motif-js/playground-bare-rn

Bare React Native counterpart to `apps/playground-native` (Expo).
Same `App.tsx`, same primitives, same demo — but on top of plain
`react-native` with Metro / Babel configured directly.

## Why two playgrounds?

`apps/playground-native` runs under Expo's vendored RN +
`expo-modules`. It's a great dev loop, but it can mask issues that
only surface in non-Expo apps: duplicate React resolution, Metro
config edge cases, peer-dep mismatches, etc.

This workspace proves motif-js works in a vanilla bare-RN setup.
Same `App.tsx` byte-for-byte (copy, not symlink, so the file is
self-contained for documentation purposes).

## Layout

The JS-side scaffolding ships with this workspace:

- `App.tsx` — identical to the Expo version.
- `index.js` — uses `AppRegistry.registerComponent` instead of
  `expo`'s `registerRootComponent`.
- `metro.config.js` — uses `@react-native/metro-config` directly
  (no `expo/metro-config`). Same monorepo-aware tweaks
  (`watchFolders`, `nodeModulesPaths`, `disableHierarchicalLookup`).
- `babel.config.js` — uses `@react-native/babel-preset` directly
  (no `babel-preset-expo`).
- `app.json` — bare-RN format (`name` + `displayName`), not Expo's
  config schema.
- `tsconfig.json` — extends `@react-native/typescript-config`.

## What's NOT shipped

The native projects (`android/`, `ios/`) are not in the repo. They
need to be initialized once before the demo can build:

```sh
cd apps/playground-bare-rn
# Use the React Native CLI to scaffold android/ + ios/ in place.
# Match the package name from app.json ("MotifPlayground").
npx @react-native-community/cli init MotifPlayground --skip-install \
  --pm yarn \
  --version 0.85.0
# Move the generated android/ + ios/ next to App.tsx, drop the
# scratch package.json the CLI creates, then `yarn install` from
# the monorepo root.
```

The reason these aren't checked in: bare-RN init produces ~1500
files including platform-specific build outputs, gradle wrappers,
and CocoaPods metadata that drift across RN versions. Keeping
those out of the repo means the demo tracks the latest RN without
manual upgrades.

## Running

After native init:

```sh
# from monorepo root
yarn install

# in one terminal — Metro bundler
yarn workspace @motif-js/playground-bare-rn start

# in another terminal — iOS or Android
yarn workspace @motif-js/playground-bare-rn ios
# or:
yarn workspace @motif-js/playground-bare-rn android
```

iOS needs Xcode + a simulator; Android needs Android Studio + an
emulator (or a USB-connected device).

## What this proves

That `@motif-js/react-native` works in a bare-RN context with the
default Metro / Babel pipeline, no Expo-specific shims, and no
peer-dep contortions. If a regression breaks bare-RN compatibility
(e.g. a missing transform Babel preset, a new dep that needs
Expo's vendored RN), the failure surfaces here before it lands in
production user apps.

## Differences from the Expo playground

The runtime behaviour is identical — same JS output, same
primitives, same theming. Differences are infrastructure-only:

| Axis            | Expo (`playground-native`)       | Bare RN (`playground-bare-rn`)                  |
| --------------- | -------------------------------- | ----------------------------------------------- |
| Entry point     | `expo`'s `registerRootComponent` | `AppRegistry.registerComponent`                 |
| Metro preset    | `expo/metro-config`              | `@react-native/metro-config`                    |
| Babel preset    | `babel-preset-expo`              | `module:@react-native/babel-preset`             |
| Native projects | Generated by `expo prebuild`     | Generated by `@react-native-community/cli init` |
| Status bar      | `expo-status-bar`                | RN's `StatusBar` (used in App.tsx)              |

If `App.tsx` ever needs to import `expo-*` modules to work, that's
a regression — the bare-RN demo should compile without any Expo
deps in the import graph.
